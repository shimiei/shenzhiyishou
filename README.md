# 神之一手

Windows 桌面围棋程序，全本地运行，不需要联网也不需要账号。外壳是 Electron 33 + TypeScript + React，运行时零第三方依赖；引擎是随包分发的 KataGo v1.18.1，由自写的 GTP 客户端驱动；棋盘识别是一条本地实现的机器视觉管线，不依赖联网模型；内置浏览器与程序之外的原生客户端窗口都能与本地局面双向同步落子；棋谱按完整 SGF 编辑。

核心能力：

- 引擎与棋力。KataGo v1.18.1，GTP over stdio。对局与分析运行在两个独立的引擎进程上，避免争夺同一块 GPU；OpenCL 与 eigenavx2（纯 CPU）双后端，启动时自动挑选。随包只带 4.7 MB 的 b6c96，b18c384nbt（93 MB，约 2630 万参数）、b28c512nbt（259 MB）与人类棋风网络 humanv0 可在程序内下载或从磁盘导入，换网络自动重启引擎。
- 规则与棋谱。自写规则引擎，覆盖提子、自杀、劫、超级劫、终局数子（中国规则与日本规则）；完整 SGF 编辑，支持变化图、注释与各类标记，棋谱树不可变，编辑全部经纯函数；每一手记录来源（human / ai），存盘保留，送引擎前移除。
- 棋盘识别。本地机器视觉管线：木色定位、网格线检测、网格拟合、交点环形取样。木色画得很亮、白子画成灰球面的客户端同样能认（亮度之外另有一条色度判据），并保留一个可选的视觉大模型接口作为兜底。
- 网页同步。内置多标签浏览器，定时截屏识别后与本地局面逐点比对，只接受"恰好差一手"，并把这多出来的一手用逐点试下的方式验证，提子与打劫都算得对。
- 客户端同步。可锁定程序之外的一个窗口（原生客户端、远程桌面画面等），落点由 DPI 感知的 Win32 助手真实点击，点击前后各有一道核对。
- 多盘与会话。每一盘独立持有棋谱树、对局设置、复盘结果与分析结论，关掉程序再打开按原样恢复。
- 工程。主进程只依赖 Node 内置模块与 Electron（`dependencies` 为空），核心算法集中在渲染进程的纯函数模块里；709 项自测断言，另有真引擎回归与三份驱动真实界面的验收脚本。

## 技术要点

### 局面怎么送进引擎

KataGo 的 `loadsgf` 只接受根节点上的摆子，第二个节点起只要出现 AB / AW / AE 就会整谱拒收（`Found stone placements after the root`）。本程序允许在任意节点摆子（摆子工具改的是当前节点，从图片接到当前谱后续时会另起一个只含摆子的节点），因此每次送引擎之前会把整条路径上的摆子收拢进根节点，并在根节点写上 `PL` 钉死轮次。

轮次必须钉死：根节点上只有摆子、没有手数时，KataGo 按让子惯例判白先，而界面按"没有手数就是黑先"显示，不写 `PL` 两边会差一个回合，实时分析会把白方的候选点当成黑方的报出来。收拢完成后，程序用自己的解析器把这份 SGF 读回来，与界面盘面逐点比对；只要有一处改动就不认，改发"纯局面"（根节点直接列出每一颗子，不带手数）。走这条退路的情况极少，例如某一步被 `AE` 拿掉的是前面某一手下的子，这种局面无法只用根节点表达。

`npm run test:engine` 把这几类局面逐条喂给真引擎，比对盘面与行棋方。

### GTP 客户端

`src/main/gtp.ts` 是一个串行命令队列的 GTP 客户端：一次只跑一条命令，支持流式命令（`kata-analyze`）逐行回调，逐条解析 KataGo 的 info 字段。

参数上有两个已修正的坑：`maxTime 0` 不是不限时，而是立刻返回一个只算过一次访问的结论；`kata-genmove_analyze` 会把这一手真的落到引擎自己的棋局上，所以每次调用之后"已同步"的缓存都必须作废。提示（按 H）按分析的访问量计算，但受设置里"每步限时"约束，默认 3 秒，到点即交出当前结论。

引擎在 Windows 上读取含中文的路径不稳定，且安装目录通常不可写，因此引擎、网络、日志与临时文件全部镜像到 `%APPDATA%\shenzhiyishou-runtime`，首次启动时复制过去，之后一直使用这一份。

### 棋盘识别

管线在 `src/renderer/core/cv/recognize.ts`：木色定位、网格线检测、网格拟合、交点环形取样。

背景色估计没有只取直方图众数：黑白子的颜色分布往往比木色更集中，会把众数带偏，因此改为边距取样、直方图众数、中位数三路互证，取三者一致的结果。

白子判据除亮度之外还有一条色度判据。部分客户端把木色画得很亮、白子画成带明暗的灰球面，白子整圈取样的亮度可能等于甚至低于木色（实测木色亮度 200、白子 190），只按"比底色亮"找白子会一颗都找不到。底色本身彩度足够高时，程序另用一条"掉色"判据：整圈取样过半是没有颜色又不暗的像素即判为白子；底色彩色成分不足时（打印图、浅底棋盘）这条自动关闭，仍按亮度判定。与格线相交的取样像素、边线上落在盘外的那一角会先排除，避免被线色与边距带偏。

截图要经 canvas 回读成 `ImageData`，取上下文时指定了 `willReadFrequently`，否则实时截取每一拍都会从 GPU 回读一遍。

识别失败时程序拒绝给出路数，不会猜一个：棋盘没有完整进入画面就报"被画面裁掉了一部分"。

### 网页同步的核对规则

对齐逻辑在 `src/renderer/core/browser/mirror.ts`，是不碰 DOM、不碰 IPC 的纯函数，可以直接喂用例：

- 两边完全一致：不做任何事。
- 恰好差一手：把这一手接到谱上。
- 差得更多，或者轮次对不上：只报告差异（例如"网页上多 2 颗，本地多 0 颗"），本地一颗子都不动。识别漏了一颗会是这样，网页上开着另一盘棋也会是这样，两种情况都不应替用户改棋。

"恰好差一手"不是靠数子得出的：程序把本地局面在每个空点挨个试着下过去，与识别结果逐点比对，因此提子与打劫都能算准。这条规则的取舍是明确的：少接一手最多补点一下，接错一手会让整盘棋跟着错下去，而且很难判断从哪一手开始错。

自动落子在点击前后各有一道核对。点击前先截一次画面，确认页面仍停在"这一手之前"的局面，防止网页上其实是另一盘棋时替对手落子；点击后在约一秒内连拍数帧，只要点的那一点上出现棋子就算点上了（颜色读错也算，颜色读错是常事），这几帧画面都没变才判"没落上"。

判为没落上的一手不会只给一句结论：程序记下它，1.5 秒后复查。页面已经与本地一致，说明那一手其实落上了，不再点；仍停在点之前的局面，才就同一点重试，最多 3 次、最长 30 秒，到点即停。两者都不是（点偏了、对方在动、不是这盘棋）就不再点，按对方局面重新对齐。核对不通过不会自动关闭开关。

注入的点击会把键盘焦点交给 webview，所以点击之后程序把焦点还回主界面。程序记住上一次识别到的棋盘矩形，下次先按它去认；网页移动位置（弹出横幅、多一行手数或比分）导致矩形失效时，改用整幅画面重新识别，而不是持续报"认不出"。

### 程序之外的窗口

`src/main/windowHelper.ts` 与 `src/main/winScripts.ts`。程序不引入任何原生模块（原生模块需要编译工具链，打包也随之复杂），Win32 的窗口枚举、矩形读取、屏幕像素归属查询与 `SendInput` 点击由内联 C# 加 PowerShell 完成。Windows PowerShell 5.1 的 `Add-Type` 使用的是旧编译器，只能写 C# 5 语法。这些脚本以真实文件写入、编译并执行，所以助手脚本自测会把它们真跑一遍，只是不做需要屏幕的那一步。

坐标一律用屏幕物理像素：助手进程把自己标记为每显示器 DPI 感知，量到的与点到的属于同一套坐标；换屏、系统缩放、远程画面被缩小显示都只影响比例换算，最后换算成界面坐标交给系统。

点击前有两道守卫：抓到的画面比例必须与窗口当前比例对得上（正在拖动窗口边缘改变大小时跳过这一拍），目标屏幕像素上最顶层的窗口必须属于目标进程。任何一道不通过就一个点都不点，并在状态行写明原因。点击之后光标移回原处，键盘焦点还给原来的窗口。

目标窗口按进程名记忆（窗口标题会随对局变化，进程名不会），手动框选保存的是比例，因此窗口移动、缩放、远程画面被缩小之后框选依然有效。

### 会话与复盘

会话文件按分支路径记录当前节点，不按节点号：棋谱重新解析之后节点号会重排。

复盘结果按节点 id 与局面特征两个条件匹配。节点 id 会被复用：退到开局重下一盘时，新着法又会拿到 2、3、4 这些编号，只按 id 与手数比对，上一盘的评点会扣到这一盘上。因此每个结果另外记一份当时的局面特征（有着法记"颜色:坐标"，没有则记盘面），三样都对得上才算数。

复盘的分档界线是亏损的胜率点：2 点以内算正常，超过 2 点为小失误，超过 5 点为失误，超过 12 点为恶手；走出引擎第一推荐时另算"最佳"。这些换算都在纯函数里，自测覆盖。

- 安装包只带小网络（b6c96，4.7 MB），大网络在程序内按需下载，因此安装包保持在一百兆以内，不会膨胀到四百兆以上。

- 卸载是常规卸载。棋谱、设置与已下载的网络留在用户目录，不随卸载删除，重装后继续可用（见"运行数据"）。
- 自行编译见"环境与命令"。仓库内不含引擎二进制与大网络，这两样需要自行补齐（见"引擎与网络"）。

## 环境与命令

需要 Node 18 以上，Windows x64。

```
npm install          # 装依赖
npm run typecheck    # 主进程与渲染进程各类型检查一次
npm run build        # 编译主进程，打包渲染进程
npm start            # 编译后直接启动（开发用）
npm run dist         # 出安装包和便携版，产物在 release/
```

图标由 `python tools/make-icon.py` 生成，README 顶部的题图由 `tools/make-banner.ps1` 生成（Windows PowerShell 直接运行，配色取自程序主题，字体为 Noto Serif SC 与 Microsoft YaHei UI）。两者改动后都需要重新运行。

自测脚本，改动规则、识别算法或窗口逻辑之后先跑一遍：

```
npm test                      # 下面五份自测一起跑
npm run test:rules            # 规则引擎：落子、提子、自杀、劫、超级劫、数子、坐标
npm run test:window           # 窗口尺寸与位置：居中、越界拉回、换屏幕、副屏更小
npm run test:ui               # 棋盘标签、切片清单完备性、会话往返、标签页规则、地址栏输入、分栏夹取、送去引擎的局面、复盘算分、双停终局
npm run test:cv               # 棋盘识别：合成几种风格的棋盘，检查黑白子判定
npm run test:winhelper        # 助手脚本：那几段 PowerShell 真写成文件、真编译、真跑一遍（只读，不碰鼠标）
npm run test:engine           # 真引擎复验：每一份局面 loadsgf 后盘面与行棋方都对得上
node tools/gtp-selftest.mjs   # 真引擎链路：启动、loadsgf、落子、分析
node tools/cv-check.mjs 图片 --answer 答案.sgf   # 图片识别的准确率回归
```

五份自测共 709 项断言：规则 70 项、窗口 37 项、界面逻辑 544 项、棋盘识别 39 项、助手脚本 19 项（其中"拒点时光标一个像素没动"量的是差值，鼠标正在被使用时记成待验，不判失败）。也可以分别直接运行 `node tools/rules-selftest.mjs`、`window-state-selftest.mjs`、`ui-logic-selftest.mjs`、`cv-selftest.mjs`、`winhelper-selftest.mjs`。

这套自测针对的是类型检查看不见的错误：悄悄下错棋、开出一个拖不动的窗口、关掉标签跳到别的页面上、把上一盘的评点扣到这一盘上、重启之后少开一盘棋、把一局棋存成两份、少认一半白子。最后一份专盯那几段交给 PowerShell 现编现用的脚本：C# 里写错一个词、鼠标动作挪到守卫之前，类型检查与其它自测都看不见，它会真写文件、真编译、真跑一遍，只是不做需要屏幕的那一步。`test:engine` 需要启动真引擎，二十多秒，因此不在 `npm test` 里。

运行中的实例也可以从外部观察：`node tools/devtest.mjs --remote-debugging-port=9223` 起一个独立配置的验收实例，再用 `node tools/live-probe.mjs "<表达式>"` 在它的界面里求值，截图与点击见 `tools/cdp.mjs`。

这些工具永远挑 `index.html` 这个页面目标（`tools/app-target.mjs`）：固定窗口那一档会多出一个落点叠层窗口，它同样是 `file:` 页面目标（`overlay.html`），标记过一次点就一直存在，按"第一个页面"或"第一个 file:"去挑就会挑到它上面，报出来是一句难以理解的 `Cannot read properties of undefined`。

`docs/shots/` 下的截图不是画出来的，是 `node tools/shots.mjs 9223` 让一个开发实例真实运行一遍拍下来的：演示棋局由引擎自己走出，棋谱馆里的棋谱是真实存入的，实时截取那张是程序真的在往网页上点击。界面改动后重新运行即可刷新，不要让 README 挂着旧版界面。这个脚本要求实例带 `--disable-gpu` 启动（`node tools/devtest.mjs --remote-debugging-port=9223 --disable-features=CalculateNativeWinOcclusion --disable-gpu`）：走 GPU 合成时画面那一路取不到帧，`Page.captureScreenshot` 会一直挂着不返回；截图与显卡无关，软件渲染已经足够。

打包之后要验证真正打出来的那一份：`npm run dist` 之后运行 `node tools/pkgtest-refresh.mjs`，它把 asar 解一份到 `%LOCALAPPDATA%\Temp\szys-pkg`，只改用户目录那一行的名字，于是这份副本与已安装的版本可以同时运行，互不干扰。有一处必须注意：Electron 先认 `resources/app.asar`，其次才认 `resources/app` 目录，所以脚本会删掉副本里那份旧 asar，否则改过的 main 根本不会被加载，跑出来的还是上一版代码、用户目录也仍是正式那一个。

```
node tools/library-accept.mjs 9223      # 棋谱馆 80 项：存两次落在同一条、另存为、导入、搜索排序筛选、
                                        # 重命名与标签、单份与批量导出（回到磁盘上核对文件）、批量删除、
                                        # 扫描收编、换目录搬移、关了再开归属还在
node tools/nudge-accept.mjs 9223        # 工具条左右推 21 项：窄窗口下溢出、箭头、滚轮、选中自动进视野
node tools/autoplay-accept.mjs 9223     # 自动落子 57 项：点完之后焦点还在程序里、网页挪位后照样认得出来、
                                        # 点不上不再自动关开关、AI 固定执一方并真的自己走，外加
                                        # 点出去没落上的四条：没接住的会重点一次、那边画得慢的不会重复点、
                                        # 一直没落上的点三次就停并如实交代、那边换了别的子就不点了按那边重新对
```

验证装机版副本时，端口换成 9444，加上 `--exe=%LOCALAPPDATA%\Temp\szys-pkg\神之一手.exe --seam`；`nudge-accept` 与 `autoplay-accept` 没有重启那两段，给端口加上环境变量 `SZYS_WIN_PATH=szys-pkg` 即可（它们按路径挑窗口，不会影响正在运行的安装版）。`--seam` 指那份程序启动时带了 `SZYS_TEST_PICK`：主进程里留的验收口子，把"另存为 / 导出 / 换目录 / 打开棋谱"这几处系统对话框的返回值直接给出，省得驱动去操作系统对话框。它只认这一个环境变量，未设置时一行都不会走到。

### 开发时同时运行两个实例

正式程序把用户目录固定在 `%APPDATA%\shenzhiyishou`，单实例锁也在那里，所以开发实例会被正在使用的安装版踢掉。要并排运行一个用于验收的实例：

```
node tools/devtest.mjs --remote-debugging-port=9223
```

它把编译产物复制一份，只改用户目录名，其余代码一字不差，于是两个实例互不干扰。`tools/probe-window.ps1` 是配套的窗口探针，可以打印窗口样式位、位置、DPI，也能模拟拖动与最大化，还能用 `WM_NCHITTEST` 问系统"这条边上按下去算不算缩放边框"。

`tools/browser-board-test.html` 是"内置浏览器截取棋谱"用的固定测试页：一页 19 路棋盘，摆着一组写死的黑白子。在程序里打开这个页面并按"截取棋谱"，识别结果应当正好是 19 路、黑 12 白 12。几个查询参数：`?style=yike` 换成另一种客户端的样子（亮橙木色、蓝格线、白子是灰球面，格线还压在棋子上层，这是白子最难认的一种），`?px=320` 把棋盘钉小，分屏矮的时候靠它把整块棋盘塞进画面，`?start=empty` 从空盘开局，`?bare=1` 只留棋盘。

这一页也能下棋：点击棋盘的交叉点落一子（按轮次决定颜色，落在已有子的位置不生效），"对手走一手"按钮或者在页面里调 `window.__opponentMove('Q16')` 让对手走棋，`window.__state()` 读出当前手数、落子记录与点击记录。实时截取与自动落子的验收就是靠它跑真实点击与真实截图。离线核对时，把这一页的截图配 `tools/browser-board-answer.sgf` 喂给 `cv-check.mjs`：

```
node tools/cv-check.mjs 截图.png --answer tools/browser-board-answer.sgf
```

## 引擎与网络

引擎是 KataGo v1.18.1（v1.18.2 只有 CUDA 构建，无独显时用不上）。程序内有两个后端：

- opencl：走核显，默认使用。
- eigenavx2：纯 CPU 兜底，核显驱动有问题时可以顶上。

网络方面，随包只带 b6c96（`models/b6c96-s175395328-d26788732/model.txt.gz`）。设置里能下载 b18c384nbt、b28c512nbt 与人类棋风网络 humanv0，也能从磁盘导入手上的网络文件。

### 从源码构建时补上引擎与网络

随包的小网络（b6c96，4.7 MB）在仓库里，克隆下来即可直接打包。引擎二进制与大网络不在仓库里：两者合计一百三十多兆，而且都能公开下载，已在 `.gitignore` 中排除。构建前自行补齐：

```
engine/katago.exe            从 https://github.com/lightvector/KataGo/releases 取 v1.18.1 的 win64 版
engine/opencl/               上面那个包解压出的 dll 目录
engine/eigenavx2/            同上，纯 CPU 兜底后端
models/kata1-b18c384nbt-s9996604416-d4316597426.bin.gz   最强网络，93 MB
```

缺少 `engine/katago.exe` 时程序无法启动引擎，所以从源码运行时这几个引擎文件是必需的。大网络不是必需的：程序内可以下载 b18c384nbt、b28c512nbt 与 humanv0，下载地址写在 `src/main/models.ts` 的 `MODEL_DEFS` 里。只有希望安装包自带大网络时，才需要手动放进 `models/`，同时修改 `electron-builder.yml` 里 models 那一段的过滤规则。

![设置：外观、对局、引擎与网络](docs/shots/05-settings.png)

换网络分两步。"设为默认"只改设置，正在运行的引擎不会当场切换（需要停掉进程并重新加载网络，大网络在核显上要十几秒）；之后下一次启动引擎或开始分析时，程序发现网络与正在运行的不一致，会自行换掉并在引擎日志里写一行。需要立即切换时用"引擎与网络"里的"立刻换成这个网络"。这段时间内引擎面板显示的是引擎真正加载的网络名，下面一行小字说明已改成哪个、何时生效。

![引擎与网络：随包的小网络与可以在程序内下载的大网络](docs/shots/06-models.png)

### 首次启动的调优

程序启动时会自行拉起引擎（面板显示"启动中"），不需要手动点"启动引擎"。调优缓存已存在时，从拉起进程到 GTP 就绪大约 21 秒（b18c384nbt，OpenCL）。

首次运行没有这份缓存：OpenCL 后端要针对运行机器的显卡搜索并编译内核参数，KataGo 会输出几十行 Tuning 进度，实测约 6 分钟（b6c96，核显），这是程序第一次打开最长的等待。结果缓存在运行目录里，第二次启动显著加快。这段等待期间界面保持响应，引擎日志面板会持续输出进度，也可以随时点"停止引擎"，下次使用时引擎自行启动。

另外，新安装的机器上只有随包的小网络，而设置里默认指向大网络，这时程序会自动退回小网络启动，并在引擎日志里写一行说明。想用大网络在"引擎与网络"里下载即可。

### 分析

实时分析使用第二个引擎进程（与对局分开，避免抢占同一块 GPU），第一次启动同样需要十几秒。这段等待在界面上是可见的：引擎面板的徽章显示"分析准备中"，候选点一栏说明分析引擎正在启动，引擎日志另有一行"[分析] 正在启动分析引擎"；就绪后分别变为"分析中"与候选点列表。分析已在运行时改动局面，重启分析几乎立即完成，不会每次重新等待。

分析运行中落一手，胜率、目差、候选点与棋盘上的形势不会先清空再填回：上一个局面的结论原地保留，新局面的结论到达后整体替换。KataGo 第一条结论来得很快（几十毫秒就有胜率，之后逐步收敛），所以这个过程基本看不出停顿。保留的这一小段时间里，面板上的数字与候选点属于上一个局面，因此此时点击候选点不会画出推荐圈，等新结论到达后才生效。关闭实时分析，或者在分析未运行时改动局面，这些数字立即清空，不会挂着旧局面的结论。

### 从内置浏览器截取棋盘

截取的是可见画面，所以整块棋盘必须完整进入画面。分屏窄到放不下棋盘时，程序不会猜一个路数，而是直接报"棋盘被画面裁掉了一部分"。这时在网页里按 Ctrl 和减号缩小页面，或者拖宽分屏，再截一次。

### 性能预期

参考配置是 Intel Iris Xe 核显加 16 GB 内存，没有独显。b18c384nbt 有约 2630 万参数，在核显上每秒数十次访问，所以用大网络对局时每步要等几秒，默认按每步 3 秒左右控时。又想快又想强需要独立显卡，这是硬件门槛。小网络 b6c96 快得多，适合随手摆棋和试手。

程序在设置里能测速，也会在启动时挑可用的后端。

## 窗口

窗口是无边框的，标题栏由程序自绘，窗口按钮由系统绘制在右上角。

第一次打开是 1500×950 居中。之后窗口的尺寸与位置记在设置里，下次按原样恢复（上次是最大化退出的，下次同样最大化）。记录的尺寸每次启动都会按当前屏幕重新夹取：更换显示器、拔掉副屏、修改系统缩放之后，窗口不会落在可见区域之外，也不会开得比屏幕还大。

最小尺寸是 960×620。

`视图` 菜单里另有三个窗口命令，用于窗口被拖乱或卡在最大化状态时：最小化、最大化与还原、恢复成 1500×950 并居中。

## 分栏

左栏、右栏、棋盘与浏览器之间各有一条可拖动的分隔条，拖动时光标旁显示尺寸（棋盘与浏览器之间显示两块各有多少像素，窗口两侧显示像素宽度），双击分隔条复位。宽度与分屏比例记在设置里，下次打开保持原样。分隔条中间有一段可见的把手，鼠标移上去整条高亮，不是一条看不见的 5 像素。

棋盘与浏览器有两种排法，在浏览器栏的 `左右` / `上下` 之间切换：

- `左右`：棋盘在左、浏览器在右，分割中间那一块的宽度。
- `上下`：棋盘在上、浏览器在下，分割高度。

两种排法的差别在于浏览器是满高的：窗口不宽时，左右分栏下的浏览器永远是一条竖窄缝，网页会按移动端排版；上下分栏下浏览器拿到整条中间宽度。未手动选择过方向时，程序按窗口比例挑一种（左右分栏下浏览器比自身还高时改用上下分栏）；选择过一次之后不再自动改变。

窗口宽度不足时按空间压缩：棋盘至少留 300 像素，浏览器那一侧至少 320 像素，左栏不低于 214，右栏不低于 240。上下分栏时保底的是高度：棋盘那一块 320，浏览器那一块 300（它自己的标签栏、地址栏与预设按钮就要占掉一百余像素）。压缩只影响显示，已经记录的尺寸仍然保留，窗口放大后恢复。浏览器栏变窄时会依次收起可由回车替代的"前往"、预设按钮与关闭分屏的叉，把空间让给地址栏。

拖动分隔条时会盖一层透明全屏遮罩：内置浏览器是网页控件，指针进入它的范围就被页面接收，不盖遮罩会让拖动中途失效；遮罩同时阻止拖动时棋盘跟着高亮、文字被选中这类干扰。分隔条本身宽 5 像素，两侧各借 4 像素作为热区。

## 多个棋盘

棋盘可以同时开多盘，标签条排在棋盘上方，操作与浏览器标签一致：单击切换，中键或标签上的叉关闭，末尾的加号新建空盘。只有一盘棋的时候这条标签栏自动收起。

新的一盘从哪来：

- 工具条上的 `新建标签`，或者按 Ctrl+T。
- `新建对局`（Ctrl+N）、`打开棋谱`（Ctrl+O）、图片识别里的"新建棋谱"同样落在新标签；图片识别的"接到当前谱后续"接在当前这一盘上。
- 工具条上的 `复制打开`，或者按 Ctrl+Shift+D：把当前这一盘整棵棋谱复制到新标签，分支、复盘结果与对局设置都带着，落点停在同一个节点上。副本算一份新棋谱（文件名清空、标记未保存，不会覆盖原件），撤销历史不带过去，此后两盘各自演化。

每一盘独立持有：棋谱与分支、当前手、未保存标记、文件路径、对局设置（对弈方式、访问量、贴目、让子）、复盘结果与分析结论。分析、复盘与机机对局同样独立，切换到别的盘不会把它们停掉，标签上挂一个角标标明该盘正在执行的动作（分析 / 复盘 / 机机）。

关闭带未保存改动的标签会先询问：保存并关闭 / 直接关闭 / 取消。`关闭其他` 与 `关闭全部` 会先说明有 N 盘未保存。棋盘上至少保留一盘，最后一盘无法关闭；误关的用 Ctrl+Shift+T 恢复。

切标签的快捷键：

| 快捷键 | 动作 |
| --- | --- |
| Ctrl+T / Ctrl+W | 新建 / 关闭当前棋盘标签 |
| Ctrl+Shift+D | 复制打开当前这一盘 |
| Ctrl+Tab / Ctrl+Shift+Tab | 下一个 / 上一个棋盘标签 |
| Ctrl+1 到 Ctrl+9 | 跳到第 1 到第 9 个标签 |
| Ctrl+Shift+T | 开回刚关掉的那一盘 |

这一套按焦点分流：焦点在界面里（棋盘、左栏、工具条）时作用于棋盘标签，焦点在内置浏览器的网页里时作用于浏览器标签页。菜单里"棋盘标签"与"视图"两栏各有一份命令，焦点不明确时从菜单执行。

引擎资源是排他的：分析引擎一次只服务一盘。在一盘上开着实时分析，切到另一盘再点分析，前者的分析会停下，被顶掉的那盘收到一句说明，标签角标随之熄灭。复盘与机机对局占用引擎时同样会顶掉实时分析，提示里会说明顶掉的是哪一盘。这是引擎的物理限制，不是可调项。

关掉程序再打开，这一批棋盘按原样恢复：标签顺序、当前是哪一盘、每盘的棋谱与落点、未保存的改动、文件路径、对局设置（保存在 `%APPDATA%\shenzhiyishou\session.json`）。分析、复盘与机机对局不会自动继续，它们需要手动开启。

## 棋谱馆

棋谱馆是一个用户选定的文件夹，里面是普通的 `.sgf` 文件，外加一份 `library.json` 索引，记录标题、对局日期、结果、标签这些信息。文件名按标题生成（`柯洁 对 朴廷桓 2024-03-05.sgf`），重名自动加序号。文件是标准 SGF，别的程序打得开，放进网盘即可同步。

![棋谱馆：列表、缩略图、标签，右栏是选中那盘的预览](docs/shots/03-library.png)

默认目录是 `%APPDATA%\shenzhiyishou\records`，旧版本"存入棋谱库"的棋谱位于此处。目录可以更换：设置里与棋谱馆页面上都有 `更换目录`，更换时可选择把现有棋谱一并迁移（先复制再删除原件，跨盘安全；中途失败则保留原件并在提示里说明）。

保存不再弹对话框：`保存`（Ctrl+S）直接写入棋谱馆，标题默认为"黑 对 白 日期"；从馆里打开的棋谱再次保存时更新原条目，不会越存越多（每一盘记录馆内编号，随标签保存，重开程序后仍然有效）。需要一份可以单独拿走的 `.sgf` 时用 `另存为`（Ctrl+Shift+S），该操作弹出系统对话框。

棋谱馆是一个整页界面，Ctrl+L 或工具条上的 `棋谱馆` 进入，存棋后的提示里也有入口；Esc 或左上角 `回棋盘` 返回棋盘，原来的局面不受影响。

- 顶栏：总数、目录路径（点击在资源管理器里打开）、搜索（标题与对局双方）、排序（保存时间 / 对局日期 / 手数 / 标题）、多选、导入 SGF、扫描、更换目录。
- 左栏：按标签、结果、路数、时间筛选。
- 中间列表：每行包含小棋盘缩略图（按需读取并缓存，不一次性读全部）、标题、黑 对 白、结果、日期、手数 / 路数、标签。行尾 `⋯` 菜单：打开、导出到…、复制 SGF、重命名、加标签、删除、打开所在文件夹。
- 右栏：选中那盘的预览与对局信息。
- 多选：勾选框、Shift 连选、Ctrl 加选、全选；选中之后顶栏浮出 `已选 N 盘` 与 `导出到…`、`删除`、`取消`。

手动放进目录的 `.sgf` 用 `扫描` 收编：解析文件头得到双方、日期、结果、手数与路数并补入索引；索引里有而文件已缺失的标记为"已丢失"，可以清除那一条索引。重命名只改馆内标题，不动磁盘文件名，避免文件被别的程序占用而失败；导出时才按标题生成新文件名，同名不覆盖、自动加序号。删除是硬删除，执行前弹出确认并说明条数，不做回收站。

## 内置浏览器

分屏里的浏览器是多标签的：标签栏上能新建（＋）、关闭（×，中键也行）、切换。每个标签是一份独立页面，切走再切回来不会重新加载，正在下的那盘棋还在。

网页里点击 `target=_blank` 的链接、或者网页自己调用 `window.open` 时，会在同一个分屏里开成一个新标签，不再弹出独立窗口，所以开着几个页面都能截取。截取棋谱认的是当前标签，不是第一个打开的页面。

标签快捷键：Ctrl+T 新建，Ctrl+W 关闭，Ctrl+Tab / Ctrl+Shift+Tab 切换。这几个键在焦点落在网页里时由主进程在网页那一层拦截，作用于浏览器标签；焦点在界面里时，同样的键作用于棋盘标签。

"截取棋谱"认的是可见画面，棋盘必须整块进入画面：分屏太矮或网页棋盘太大时，先拉宽分屏、切成上下分栏，或者把网页缩小（Ctrl 加 / 减号）再截。识别只针对通用的棋盘画面，不对任何具体网站做适配。

### 实时截取

浏览器栏上有两个开关，默认都关着。

![实时截取：分屏里网页与本地各一盘棋，状态行写着两边一致](docs/shots/02-live-capture.png)

"实时截取"开着的时候，程序每隔两三秒截一次当前标签的网页画面，识别出棋盘，与本地这盘棋比对（"自动落子"也开着时缩短为 1.2 秒一拍，因为两边必须完全一致才点得出去）：

- 完全一致：状态行写"和网页一致"，不做任何操作。
- 网页比本地多恰好一手：把这一手接到谱上（提子与打劫都算得对，因为是把本地局面挨个空点试着下过去比对，不是数棋子）。状态行写"接上网页的一手：Q16"。
- 差得不止一手：只报告差异（"网页上多 2 颗，本地多 0 颗"），本地棋盘一颗子都不动。可能是网页上开着另一盘棋，也可能是识别漏了一颗，这两种情况都不该替用户改棋。
- 轮次对不上（例如轮到黑走、网页上却多出一颗白子）：同样按对不上处理，不硬接。

判定理由见上文"网页同步的核对规则"。

自动落子点出去、但当场没有核实的那一手，也走这里"重新对一次"：在这一手仍待核实期间，实时截取不会拿"本地多一颗"去念它（那本来就是这一手造成的），而是先把这一手办完。

网页棋盘必须完整、而且足够大地出现在浏览器那一块里才能识别。识别不出来时状态行会给出原因与处理方式：找不到网格说明棋盘太小（把分隔条往棋盘那边拖，让浏览器那一块大一些，或者在网页里按 Ctrl 加号把棋盘放大），报"被画面裁掉了一部分"说明没有完整入画（用 Ctrl 减号缩小网页，或者改用上下分栏）。首次识别成功后，程序会记住棋盘在画面里的位置，之后先按这一块去认；网页移动位置（弹出一条消息、多一行手数或比分）导致这一块对不上时，改用整幅画面重新识别，不会一直报"认不出"。

上下分栏时浏览器那一块往往又宽又矮，棋盘按高度缩得很小，这种排法下实时截取多半识别不出来；改用左右分栏，或者把分隔条往上拖。

### 自动落子

"自动落子"开着的时候，在本程序里落下的子会真实点击到网页棋盘上（点一下就是落子，和手点一样）。规则如下：

- 只点击本程序产生的着法：用户点击的、AI 走出的。由实时截取从网页读回的那一手不会再点回去。
- 点击前先截一次画面，确认网页上仍是"这一手之前"的局面。对不上就不点，状态行说明原因。这是防止网页上开着另一盘棋时，替对手往别的棋盘上落子。
- 点击后连拍数帧核对，一共看一秒多：只要点的那一点上出现了棋子就算点上了（颜色读错也算，读错颜色是常有的事）；这几帧里网页上仍是原样，才说"没落上"；网页上变了、但不是所点的那一点，说明点偏了；这几帧都没识别出棋盘，就照实说不确定，不下结论。
- 当场未能核实的那一手不会只给出一个结论就结束。程序会把这一手记下来，过一会儿再看一眼两边的棋盘：那边已经和本地这盘一样了，说明其实落上了，不再点（那一格上已经有子，再点也变不出别的来）；那边仍停在点之前的局面，说明这一下确实没点进去，就着同一点再点一次；两样都不是（点偏了、那边别人在动、或者根本不是这盘棋），就不再点，按那边的局面重新对一次。每 1.5 秒看一回，最多点 3 次、最长 30 秒，到点就停。
- 停止之后本地这一手保留，不会被自动删掉。实时截取下一拍会比出"本地多一颗"，那句提示会点明多出的大概就是没落上的那一手（"点了 3 次那边都没出现"），并说明处理方式：在网页上补上这一手，或者撤销本地这一手，两边就恢复一致。
- 核对不通过不会自动关闭开关。开关状态、已点次数与停在哪里都写在状态行里。
- 在这一手仍待核实期间，如果再落一手，程序会先把上一手处理完（该重试的重试），处理不下来就只提示、这一手先不点，不会让两边的差异越拉越大。
- 程序记住上一次识别到的棋盘矩形，下一次先按它去认；网页移动位置（多出一条横幅、手数栏、比分栏）导致矩形失效时，改用整幅画面重新识别，而不是直接报"认不出"。
- 点击之后键盘焦点留在程序自己这一边，不会跟着那一下点击进入网页（注入的点击本来会把焦点带给网页，程序点完会取回来）。
- 停一手无法自动点击，状态行会提示在网页上自行处理。

两个开关建议一起开：对手在网页上走，实时截取把它接过来；在程序里落子（自己走的或 AI 走的），自动落子把它点过去。只开自动落子而不开实时截取时，网页上对手那一手接不回来，两边会越走越对不上，因此这时开启自动落子的提示里会说明这一点。

### 白子为什么不能只看亮度

部分客户端把木色画得很亮、白子画成带明暗的灰球面，白子整圈取样的亮度与木色相当甚至更低，只按"比底色亮"找白子会一颗都找不到（实测：木色亮度 200、白子 190）。所以底色本身彩度足够高时，程序另用一条"掉色"判据：整圈取样过半是没有颜色又不暗的像素，就是白子；底色彩色成分不足时（打印图、浅底棋盘）这条路自动关闭，仍按亮度判定。与格线相交的取样像素、边线上的子落在盘外的那一角先排除，免得被线色和边距带偏。

## 固定窗口

内置浏览器那一档认的是网页画面。这一档认程序外面的一个窗口：原生围棋客户端、远程桌面里的画面、别的程序开着的棋谱窗口都可以，只要在屏幕上看得见。

在浏览器栏最上面那排切到"固定窗口"，接下来几件事都在下面那块画面预览上做：

- 选窗口：点"选窗口…"，列表里列出当前屏幕上看得见的窗口（本程序自身不列）。选中之后程序按进程名记忆（窗口标题会随对局变化，进程名不会），下次打开这一档自动接回来；目标窗口关闭或最小化时状态行会说明。
- 认一下：识别成功后把路数和子数写在按钮旁边，并在预览上描出识别到的棋盘与棋子。
- 框选：识别不出来时在预览上拖一个框把棋盘圈进去，之后一直按这一块识别。存的是比例，所以窗口移动位置、改变大小，甚至远程画面被缩小显示，框都仍然成立。旁边的按钮清除框选。
- 标一下：把当前这一手（没有着法就取天元）在那个窗口上画一个环，用来核对程序算出的位置。
- 落点提示：开启后，每次真实点击之前先在那个位置画一个环。

识别出的棋与网页那一档走同一套流程：实时截取会把窗口里多出来的一手接到谱上，自动落子会把程序里的着法真实点到那个窗口里。区别只在最后一步：网页那边是往 webview 里注入点击，这一档是真的移动鼠标点过去。

真实点击前有两道守卫：先核对画面比例与窗口当前比例是否对得上（正在拖动窗口边缘改变大小时，这一拍不点，下一拍重新识别之后再点），再核对那个屏幕像素点上最顶层的窗口是否属于目标进程（不是就一个点都不点，状态行写明"那一点上盖着别的窗口"）。点击后光标移回原处，键盘焦点还给原先的窗口。目标窗口被完全压住时，它不会硬点。

多显示器、系统缩放、远程画面里的缩小显示都不影响落点：窗口测量与光标移动交给一个先把自己标成"每显示器 DPI 感知"的助手进程，量到的与点到的都是同一套物理像素，中间全靠比例换算，最后换算成界面坐标那一步交给系统。

## 对弈方式

对弈方式有三档，在"新建对局"里选：

- 辅助：AI 不自己落子。按 H 或点"提示"给出建议，并说清这一手是给哪一方的（"白棋推荐 Q4 · 白方胜率 62.9% · 领先 1.0 目"），棋盘上同时画一个同色的半透明子加金圈，只供查看，不代为落子。需要 AI 顶一手时按空格或点"AI 走一手"，走完就停，下一步仍然等待。
- 人机对局：AI 自动走对手那一方。
- 机机对局：双方都自动走，用来看棋。

机机对局不必从"新建对局"开：工具条上的 `机机对下`（或者按 M）随时能开、随时能停，从当前局面接着往下走，不是重开一盘。状态行最左边那句写着现在的档，点它同样管用。正算着一手的时候按停，那一手会照常落下并在提示里说清；之后再不会自己走。

只想让 AI 固定执一方时，用 `机机对下` 旁边那两颗：`AI 执黑` 与 `AI 执白`。点哪一颗，AI 就固定执哪一方，另一方全归用户；轮到它的时候它自己走，与人机对局是同一件事。再点一下同一颗就收回来，回到辅助模式。两颗都不亮就是辅助模式。开着机机对局的时候这两颗不亮（两边都归 AI）。这一档不写入棋谱文件：棋谱本身仍按 SGF 的规矩记，交给别的程序不会多出一份"谁该走"的人为信息。

于是看完整的一盘棋只要三步：点 `机机对下`，等它下完（中途点 `停机机` 也行），再按 R 复盘。一路走下来的每一手都记着来源是机器，复盘清单里"人 / 机"那一栏看得出来。

搭配使用时的几点说明：

- 提示按"现在轮到谁"计算，胜率与目差也是行棋方视角，所以同一句里两个方向一定是同一个视角，不会看串。
- 盘面一变（落子、摆子、撤销），手里的推荐立刻作废，不会留个圈在旧局面的点上。
- 摆子的局面（从图片导入的图、自己摆的开局）没有手数，程序按惯例判黑先。轮到谁由用户指定：状态栏那个"换先手"按一下改成白先，之后提示与分析都按新的走。有手数的局面轮次跟着手数走，这个按钮不出现。
- 从图片识别出来的局面默认落在辅助档，识别完直接按 H 取建议，不会莫名其妙多出一手。
- 机机对局自己收尾：两边连着停一手就停，档退回开之前那一档，并打开形势判断；再点 `机机对下` 会说明这盘已经下完了。开着机机的时候去翻前边的棋、撤销、摆子都不会另起一手，要接着自动走就再点一下。

## 复盘

一整局下完（或者从棋谱馆里翻出一盘别人的棋）想知道哪儿下得不好，按 R 或者点工具条上的"复盘"。引擎会把这一局的每个局面挨个算一遍，然后给出结论：

![复盘：胜率曲线、逐手清单、问题手](docs/shots/04-review.png)

- 上方是胜率曲线，深色是黑棋的胜率、下面浅色是白棋，曲线上带颜色的点就是问题手，红点越大亏得越多。点曲线能选中某一手，双击直接跳过去。
- 下面是逐手清单：黑白、手数、坐标、评语（最佳 / 正常 / 小失误 / 失误 / 恶手）、亏了几个胜率点、引擎推荐的那一手，最右边是这一手是谁下的（人 / 机）。默认只列问题手，切"所有着手"能看全部。
- 右边一块小棋盘跟着选中的那一手走，下面写清这一手之前的胜率、亏掉的目数、推荐的着点，以及每手算到了多少次访问。
- 左下角是统计：共几手、恶手几处、失误几处，以及人下的手和机器下的手各平均亏多少。工具条上的"上一处问题 / 下一处问题"可以不打开这个窗口就一处处看过去。

两个实现上的取舍：

- 每个局面的访问量在设置里调（默认 150，也能在复盘窗口里直接拖）。一整局几百手，核显上先用 100 到 200，跑得动再加。跑的时候工具条上写着"复盘 12/35"，随时可以点"停下"。
- 结果按节点存，中途停下、程序关掉之前算完的部分都留着：再打开窗口点"接着算"就从断的地方往后跑，点"重算"才从头来。复盘要独占分析引擎，所以它一开始跑，实时分析会停下来；反过来点实时分析时，复盘让位并在提示里说明，已经算完的部分照样留着。

一盘棋的每一手是谁下的，程序记在 SGF 的自定义属性 `SRC` 里（`human` 或 `ai`）。左侧结构、复盘清单里那个"人 / 机"就是读它，存盘再打开也还在。导入的棋谱没有这个属性，所以不标；这个属性只在本程序内部用，送去引擎之前会摘掉。

## 运行数据

## 已知限制

- 大网络在核显上每步需要几秒，深度学习分析更慢。
- 图片识别对拍照的透视变形和强烈反光还不够稳，识别结果可以手工点着改，这是设计上就留的兜底。
- 内置浏览器截取的是可见画面，棋盘没有完整进入画面、或者小到认不出来时会被拒绝识别，得先缩小网页或者把分屏里浏览器那一块调大。实时截取与自动落子用的是同一套识别，同样受这条限制。
- 固定窗口那一档要认得着那个窗口里的棋盘：目标窗口被别的窗口完全压住时，能不能接着抓到画面取决于对方程序，有的程序被判定成"被遮挡"就停止绘制，抓到的是一张黑图。这时程序会如实报告识别不出，不会乱认更不会乱点，把那个窗口露出来一点就恢复正常。真实点击同样要求目标窗口在最上面，被压住时一律不点。
- 固定窗口认的是整个窗口的画面，窗口里除了棋盘还有一堆按钮和文字，所以多半要用"框选"先把棋盘圈出来再识别；框选存的是比例，窗口挪位置、换大小之后不用重框。
- 实时截取最快也就两三秒一拍（自动落子开着时 1.2 秒一拍）：截一张加识别一次要两三百毫秒，网页落子之后往往还有动画，截太勤容易拍到没有落定的画面。
- 程序窗口被最小化时，截取网页会一直挂着不返回（要等到有画面才给图），所以这一档当场就不截了，直接在状态行说明"程序窗口被最小化了，没有画面"，恢复之后下一拍自动继续。卡住的那一拍也会被清理：一拍超过 15 秒还没回来，下一拍就重新开始。
- 视觉大模型识别需要自行填写兼容 OpenAI 协议的地址、模型名与 key。请求由主进程代发：界面自身的 CSP 是 `connect-src 'self'`，在页面里直接请求外部接口会被拦成一句"Failed to fetch"，看着像地址写错了。填好之后设置里会说明可以直接使用；请求失败时界面上显示状态码与服务端的原话，不含混成"格式不对"。
- 窗口拉到最窄（960 宽）又开着分屏浏览器时，两侧栏会被压到最小，中间只剩四百多像素给棋盘与浏览器分。压缩到限位，不是不能拖：宽度记着，窗口一宽回来就恢复。
- 分析引擎一次只服务一盘：多盘同时开实时分析做不到，后开的那盘会把先开的顶掉，被顶掉的那盘会收到一句说明。机机对局在后台继续走时也会顶掉别盘上正在跑的实时分析（对局引擎与分析引擎抢同一块 GPU）。
